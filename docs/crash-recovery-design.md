# Laniakea 崩溃与强退恢复设计

角色：恢复语义、实现边界与验收设计；不作为当前版本已经通过的证明。本文不改变现有
Markdown 权威、自动保存、备份或退出握手语义；它补足正常退出回调无法覆盖的进程
崩溃、强制结束和系统掉电窗口。稳定签名、受保护目录授权延续与安装态替换属于独立
发行 lane。

## 目标与边界

- 已经在画布上成立的结构操作，在进程异常结束后应尽量恢复。
- 正在输入但尚未按 Enter 或失焦的标题、节点、流程节点和分支名称也进入恢复范围。
- 恢复稿永不绕过源文件 revision 检查，永不静默覆盖外部较新的 Markdown。
- 没有真实恢复候选时不显示提示；发生恢复时沿用底部紧凑反馈载体，不增加恢复首页、
  侧栏或常驻状态面板。
- `SIGKILL` 和掉电不会执行退出代码。产品不能承诺绝对零丢失；目标是把已接收输入的
  未持久化窗口压到一个可测量的短区间，并对超出边界保持诚实。
- 现有最多 8 份备份继续表示“已提交正文的旧版本”；恢复检查点表示“尚未提交到
  正文的最新工作”。两者不可混为一种文件或一种提示。

## 与既有保存模型的关系

正文仍按原有 320ms 防抖保存、视口仍走 900ms 辅助状态路径；恢复保护现在独立于二者：
结构内容变化立即排队写完整检查点，编辑框用 72ms 合并的小草稿保护尚未提交文字。
启动读取权威正文后按源身份、摘要和 generation 合并候选。桌面、恢复写回和 MCP 对同一
规范路径复用同名跨进程锁，并在最终 rename 前再次校验 revision。正常退出继续走保存
握手；强退安全不依赖退出回调或崩溃处理器。

## 双层恢复记录

### 1. 文档检查点

每次文档内容代次变化后，写一份应用数据目录内的紧凑 JSON 检查点。它至少包含：

- 格式版本、会话 ID、单调递增的 generation 和保存时间；
- 当前文档路径、受保护源路径与该源在编辑开始时的内容摘要；
- 完整 `MindMapDocument`，包括 Space 语义和本地视图状态；
- 文档内容摘要，用于识别“正文已经保存、只是清理未完成”的重复候选。

检查点使用固定长度临时文件名、`sync_all`、原子替换和父目录同步。请求按 generation
串行；迟到的旧请求不能覆盖新检查点，清理操作也只能清除不晚于已提交 generation 的
记录。

内容检查点先于 320ms 正文自动保存，但不得在每次 pointer move 或视口采样时重写完整
文档。拖拽只在最终提交位置后产生内容检查点；纯视口变化沿用更慢、可丢弃的辅助状态
路径。

### 2. 编辑草稿记录

标题、思维节点、流程节点和分支名称在编辑时写小型草稿记录，而不是每个字符重新复制
整张 10,000 节点文档。记录包含会话、generation、当前 Space、对象类型、对象 ID、
草稿文本和对应文档检查点 generation。

- 普通输入按短防抖合并；IME 预编辑只在 `compositionend` 后写入可恢复文本。
- Enter、失焦或显式提交后，先形成新的文档检查点，再清理已被该检查点吸收的草稿。
- Esc 放弃编辑时清理草稿，不能在重启后复活已取消文字。
- 文档切换、撤销、删除对象或删除 Space 时，以会话和对象身份使旧草稿失效。

## 启动时的合并规则

启动先读取权威 Markdown，再读取恢复记录并验证 schema、文档身份与 generation：

1. 没有候选，或候选内容与当前正文等价：安静清理候选并正常打开。
2. 源文件摘要仍等于检查点的基线：显示恢复后的画布，但暂停把它自动写回正文；底部显示
   `已恢复上次中断前的内容`，提供 `保留` 和 `放弃`。继续编辑等价于保留。
3. 源文件已修改、移动或删除：不覆盖源文件，把恢复内容物化为独立的应用草稿，并提示
   `原文件已有变化，恢复内容已保留为副本`。
4. 未绑定 rich 副本的检查点没有可比较的权威源文件：统一按规则 2 返回为待决恢复
   （`保留` 时物化为独立草稿），不依赖旧版 `.mindmap.json` 是否存在来决定走向。
5. 检查点损坏或引用的对象已不存在：保留原始恢复文件到 `recovery/`，打开权威正文，
   给出可见但不阻塞的失败说明。隔离区最多保留 20 份损坏记录，超出时淘汰最旧者。
6. 同一恢复候选连续两次导致启动未完成：下一次不再自动载入候选，先打开权威正文，
   同时保留候选为安全副本，避免崩溃循环。

正常保存成功后，只有在保存目标、document generation 和当前会话仍一致时才清理恢复
记录。保存完成后又发生的新编辑必须留下更高 generation 的候选。generation 只允许
前进：写入方维持不低于已采纳记录的下限，存储侧对更低 generation 的写入返回可见
错误而不是静默当作已写入。

## 交互形态

恢复不是独立页面。底部反馈条仅在有候选时保持可见：

- 无冲突：`已恢复上次中断前的内容` + `保留` + `放弃`；
- 有冲突：`原文件已有变化，恢复内容已保留为副本` + `另存为`；
- 恢复保护写入失败：`临时恢复保护不可用` + `重试`，正文自动保存仍独立工作。

待决横幅是持续型通知：它被短暂消息（如显式保存的 `已保存`、撤销提示）临时顶替时，
短暂消息淡出后横幅必须回来；点击 `保留` / `放弃` 不立即关闭横幅，由动作结果决定
横幅去留。任何成功的内容提交（显式保存、首次编辑、切换前保存）都等价于 `保留`，
横幅随即撤销，不再对已提交内容提供 `放弃`。

提示必须可键盘到达、读屏可理解，并在动作后返回画布。它不能遮挡文档切换器、节点或
流程工具条。恢复内容未决时，新建、打开、最近文档切换和退出都先执行与当前文档相同的
保存/保留规则，不能悄悄丢弃候选。

## macOS 生命周期策略

- 保留现有自定义应用菜单 `Command+Q` 保存握手和窗口关闭握手。
- 不把 Tauri `ExitRequested`、AppKit delegate、信号处理器或 panic hook 当作崩溃恢复
  的唯一触发器；这些路径都无法覆盖 `SIGKILL` 和掉电。
- 如需补齐 Dock 的正常“退出”，只增加一个窄的 app-level AppKit 终止协商桥，数据状态
  仍由 React/存储层拥有。该桥是体验增强，不是数据安全基础。
- 不在崩溃处理器里写 Markdown、创建备份或执行恢复合并。

## 性能约束

恢复实现不能以“多写一次整图”默认换取安全。实施前后在同机同 fixture 记录：

- 1,000 / 10,000 节点的检查点序列化、IPC、原子写入和同步 p50/p95/p99；
- 普通输入、IME 提交、结构操作、拖拽释放到可见反馈与检查点完成的延迟；
- 10,000 节点 pointerdown、首次移动、持续移动和释放帧分布；
- 连续编辑 10 分钟后的 renderer/Rust RSS、heap、文件描述符、临时文件和恢复目录大小；
- 自动保存与恢复写入同时发生时，最终正文、检查点 generation 和 UI 保存状态。

`npm run measure:overview-drag` 从真实文件输入导入 9,999 节点，验证全图挂载、放大后的
视口窗口收缩、重复真实 pointer 手势、布局提交、取消、heap 与残留状态。脚本
把首次反馈明确记为 DOM 属性 mutation，不冒充已经绘制的像素；释放稳定时间也明确包含
六个稳定帧的观察下限。每次评审保存原始输出到当次 CI/任务记录，做同环境多轮
before/after；长期设计文档不固化某次机器的结果。

`npm run measure:bundle` 输出每个 chunk 的原始/gzip 字节和模块归因。拆包结论必须区分
入口解析与缓存边界、按需加载和全部 JavaScript 总量，不能以警告消失冒充总传输改善。

## 故障注入验收

所有桌面场景使用独立 bundle ID、独立应用数据目录和临时 Markdown，不碰安装态客户端：

1. 节点、标题、Flow 节点和边标签输入后不按 Enter，直接 `SIGKILL`，重启后恢复最终已接收文本；
2. 新建、删除、重排、下钻、拖拽释放后，在正文防抖结束前 `SIGKILL`，重启后结构完整；
3. 在检查点临时文件写入、同步、rename 和目录同步各阶段中断，重启只接受完整旧版或新版；
4. 在 Markdown 备份、正文替换、画布状态写入和备份清理各阶段中断，正文不出现半写文件；
5. 检查点形成后由外部编辑器修改、移动或删除源文件，恢复稿成为独立副本；
6. 检查点损坏、磁盘满、权限拒绝、连续二次恢复崩溃时，权威正文仍可打开且错误可恢复；
7. 正常 `Command+Q`、菜单退出、Dock 退出与关闭窗口后没有伪恢复提示；
8. 恢复未决 -> 新建/打开/另存/退出，以及恢复 -> 再编辑 -> 再强退，最终目标文档和残留文件正确。

## 实现职责

1. 建立恢复格式、原子存储、generation 清理、损坏隔离、启动循环保护和可控写入
   中断点；故障注入至少覆盖临时文件同步后、rename 后的中断，以及锁持有者崩溃后的接管。
2. 大图测量拆成 pointerdown、首次 move、首次反馈 mutation、持续帧、布局释放处理、
   六稳定帧观察、heap 和残留检查；可读缩放不能沿用全图概览的完整挂载窗口。
3. 桌面 Markdown、恢复和 MCP 复用同一路径锁/CAS 语义；真实双进程写入必须得到一次
   提交、一次 conflict。
4. 对构建包先做模块归因，再决定入口、React、Markdown、Graph 和 Flow 的缓存或按需
   加载边界；同时报告入口与总 JavaScript，不能只追逐单个 chunk 数字。
5. 稳定签名、Downloads/Documents 授权延续、公证与安装态升级在发行候选上单独验证；
   ad-hoc 包不能替代发行 lane。

## 完成标准

完成不是新增几个单元测试。必须同时满足：开发回归 PASS；隔离新 `.app` 的故障注入与
重启读回 PASS；恢复实现没有让代表性和 10,000 节点交互出现可归因退化；原安装态保持
未触碰，直到 owner 明确授权安装；最终视觉与顺手程度仍由 owner 给 `OK / 不OK / 待验收`。
