# Laniakea review contract

本契约定义 Laniakea 在前端编辑器、浏览器持久化、Tauri 桌面文件流与 Agent
Markdown 工具之间的项目级审查边界。它要求按连续状态和真实持久化结果审查，
而不是把纯函数测试、截图或一次成功保存提升为“数据安全已通过”。

这里列出的是已知高风险接缝和最低覆盖，不是功能穷举或完成清单。审查者必须先从
当前源码与真实运行重建可见对象、操作、状态和暗示，再执行至少一条不取自本文标题、
测试名、旧发现或改动文件列表的独立探索路径。界面或选择模型合理暗示但产品模型未
列出的操作仍须报告为“已确认缺陷”“合理暗示但尚不支持”或“新产品建议”之一；
逐项跑完下列内容不能单独结束审查。最终报告必须写明独立路径、契约外发现以及仍未
覆盖的当前组合；没有新发现时也要写明实际探索了什么。

先读 `product-model.md` 与 `agent-tool-model.md`。当前文档、文件、运行时和安装包
控制事实；旧报告、fixture、自生成 receipt 和绿色检查只控制它们实际观察到的部分。

## 权威与载体

- `src/types/mindmap.ts`、`src/model/document.ts`、`tree.ts`、`markdown.ts`
  拥有共享文档、树完整性、Markdown 导入/导出与 rich-source 保护语义。
- `src/hooks/`、`src/persistence/` 和 `src/desktop/` 拥有前端会话、文档切换、
  浏览器 revision、恢复、保存生命周期与平台分支。
- `src-tauri/src/storage.rs` 拥有桌面 Markdown、草稿、活动文档、辅助画布状态、
  备份、外部修改检测与原子文件替换；`lib.rs` 拥有退出握手、窗口和全局快捷键。
- `src/agent/mindMapTools.ts` 是 Agent 结构操作投影；`mcp/mindMapFileStore.ts`
  拥有显式 Markdown 路径、内容 revision、跨进程锁、原子更新；`mcp/server.ts`
  与 `plugins/laniakea/` 只是传输与发行载体，不得建立第二套导图模型。
- `src/commands/registry.ts` 拥有快捷键、命令身份与画布交互目标的能力映射；
  `src/model/canvasInteraction.ts` 拥有思维节点/Space 概要目标身份和过期目标判定。
  UI、键盘与命令面板只是适配入口：同一命令 ID 不得按目标改换语义，目标不支持的
  命令不得展示或下发，过期 Space 目标不得回退到普通节点 mutation。
- `src/hooks/useDragInterruption.ts` 拥有直接操作的宿主中断仲裁；各画布只注册当前操作
  与取消策略，不得各挂一套顺序相关的全局 `Esc` 监听。Flow 键盘入口接收明确的节点或
  连线目标状态，不以 DOM 属性查询代替交互目标。
- 网页、桌面和 Agent 可以读取同一 Markdown 内容，但本地画布坐标、折叠、视口、
  最近文档与恢复状态不是 Agent 可编辑内容，也不应写入可携带 Markdown。
- 当前没有 Laniakea Capability Profile、Provider Manifest 或 Procedure binding。
  在明确资源身份、revision、冲突、写入效果和外部 observer 前，不得把“工具存在”
  报成 Capability/Procedure conformance。

## 共享内容与无损边界

1. **一份 Markdown 内容模型。** 有意义的一级标题是文档标题；精确的“未命名思维”
   是临时占位，已有文件按有意义文件名、主原点顺序补全，新空白稿在首次提交非空
   主原点时确定标题。第一个顶层列表项是主原点，后续顶层列表项是浮动分支；嵌套
   列表表达有序子树。Agent 编辑标题、节点文字、父子关系和顺序，不编辑选择、缩放、
   坐标、折叠或视觉样式。
2. **rich Markdown 可读但不可原位降级。** CommonMark/GFM 的表格、代码、任务、
   段落等可以进入画布；只有可无损往返的纯大纲允许原位写回。rich source 必须
   以未绑定副本打开并另存为不同 Markdown，原文件内容和路径始终不变。
3. **引用只属于一次 revision。** `/0/1/...` 结构引用按当前顶层与子节点顺序生成，
   不能跨 revision 缓存。一个 update batch 内，所有 ref 指向该批开始时读取的
   原始节点；移动前后仍指向同一原节点，新建节点不能凭猜测在同一批被再次引用。
4. **树结构始终完整。** 恰有一个不可删除、不可移动的主原点；浮动根无 parent；
   每个非根节点恰有一个父节点；不存在循环、重复引用、孤儿或失配索引。移动到
   自身/后代、删除主根、越界 position 和前序操作已删除的目标必须整批失败。
5. **预览不承诺提交。** `dryRun` 必须走相同解析、rich 保护、ref 与结构校验并且
   不写文件；它不持锁，因此只说明当时 revision 上的候选结果。真正提交仍须再次
   检查同一 `expectedRevision`，并允许诚实返回 conflict。

## Agent 文件与并发写入契约

- 四个工具固定为 `read_mind_map`、`search_mind_map`、`create_mind_map` 与
  `update_mind_map`。前两者只读；create 只创建不存在的文件；update 可删除内容，
  因而是可见、非幂等、destructive 的宿主审批操作。工具不扫描目录、不猜文件，
  只接受调用方明确给出的绝对 `.md`/`.markdown` 路径。
- 读取和更新拒绝目录、非普通文件与最终路径本身是符号链接的对象；创建要求父目录
  已存在并用 exclusive create 拒绝覆盖。审查时另测父目录别名、规范化别名、长合法
  文件名、权限、不可写目录、文件在检查后被替换，以及大小检查与读取之间的竞态。
- revision 是原 Markdown 字节的 `sha256:` 摘要。更新在规范化 real path 上用同目录
  锁串行化别名访问，锁等待上限 10 秒，陈旧锁阈值 5 分钟；持锁后重读 revision，
  生成同目录临时文件、同步、再次重读 revision，再原子 rename，并保留权限 mode。
- 任意失败都必须满足：旧正文未被部分覆盖、并发较新正文未丢失、临时文件和锁最终
  清理、create 不覆盖、rich source 不写。两个进程用同一 revision 并发更新时恰好
  一个提交、一个 conflict；这个结论必须在真实进程与路径别名上验证。
- 结构输入上限是每张 Agent 可更新导图 10,000 节点、创建分支深度 64、每批
  1–100 个操作、节点文字 20,000 字符；文件读取上限是 8 MiB。read 默认返回
  500 节点、8 层，MCP 上限 5,000 节点；search 最多返回 500 个匹配，但必须扫描
  全部已接受节点并以 `truncated` 说明遗漏。

MCP 可预期失败必须返回 `isError: true`，并在 `structuredContent.error` 保留稳定
`code + message`；未知系统失败收敛为 `permission_denied` 或 `io_error`，不能把任意
内部错误文字原样上网。完整工具请求上限为 512 KiB，必须在任何文件副作用前检查；
成功与失败的完整工具结果声明 256 KiB 上限；实现把工具结果
控制在 240 KiB 内，为协议包装预留 16 KiB。文本 summary 最多预览 12 个节点；结构化
节点、超大 scalar 或 breadcrumb 超出预算时必须在节点边界或明确标记的 scalar 前缀
处截断，并通过 `truncated`、`truncationReasons` 与 `*Truncated` 字段说明。审查要同时
序列化成功和错误结果，不能只数节点或只量 structuredContent。

## 网页持久化与多标签页

- IndexedDB 中每个文档拥有独立 ID 和递增 revision；活动文档指针与正文记录在同一
  必要事务中更新。旧标签页只能在 expected token 与当前 revision 一致时保存，否则
  保留较新版本并给当前内容提供可下载/恢复的安全出口。
- 新建、切换、导入、恢复与打开都必须先保存当前文档；保存失败不切换。所有异步
  文档动作共享代次，较晚的用户意图使较早未完成的读取/激活/草稿准备失效，后完成
  的旧 promise 不能替换当前画布或活动文档。
- 完整浏览器备份带明确 format/version，导入时创建新副本而不覆盖；恢复快照发生
  revision 冲突时也保留为独立副本。旧 localStorage 数据迁移、损坏记录、IndexedDB
  blocked/quota/permission、无痕模式和站点数据清除边界分别验证。
- File System Access API 是可选增强，不能成为唯一导出/保存通路。UI 必须诚实说明
  “保存在此浏览器”，不得暗示账号、云同步或跨设备安全。

## 桌面文件、恢复与退出序列

恢复候选的格式、代次、合并与故障注入边界见
[`crash-recovery-design.md`](crash-recovery-design.md)；它是语义设计，不是当前运行通过记录。

- 新建立即生成独立 Markdown 草稿；打开/导入/另存前先保存当前文档。用户目录文件
  与应用草稿的另存语义不同，但 UI 只呈现一个“另存为”：草稿成功迁移后才清旧稿，
  用户文件则保留原件并切换绑定。
- Markdown 正文是权威；画布辅助状态用正文摘要绑定。外部修改、移动或删除后停止
  覆盖并保持可见失败状态。正文原子替换成功后，即使辅助状态或旧备份清理失败，也
  返回非致命 warning 并继续使用新摘要，不能把已提交正文误报为未提交。
- `.mindmap.json` 只作旧版兼容/恢复；打开后成为副本，绝不覆盖原备份。损坏恢复、
  最多 8 份备份、旧 hash/state 迁移和缓存失效必须用真实磁盘状态验证。
- Downloads、Documents 等受保护目录要验证：文件面板选择 -> 首次系统授权允许/拒绝
  -> 同目录临时文件原子替换 -> 重启后再次保存。分别记录开发临时签名和稳定发行签名；
  不得通过直接覆盖正文来换取无提示，也不得把一次授权通过当成重建后仍有稳定身份。
- 点击关闭：保存成功后隐藏窗口，失败则保持可见。`Command+Q`：原生层先阻止首次
  退出并通知前端，前端保存最新文档后才批准退出；监听器未就绪、重复退出请求、保存
  失败、保存中再次编辑和保存完成后的真实进程退出必须按一个连续序列测试。
- 全局快捷键替换是事务式的：先验证/注册新键，再撤销旧键并保存；任一步失败要回滚
  到仍可用的旧键。窗口显示/聚焦、复制路径、Finder 定位与 capability 权限在新构建
  `.app` 上验证，不能由 mock 或 Rust 单测代替。

## 编辑器连续状态与体验风险

下列组合是高频回归对象，必须从用户入口触发并断言最终画布、当前文档、磁盘/IDB
对象和残留状态，而不是分别测 A 与 B：

- 编辑中保存 -> 新建/打开/最近文档切换；保存失败 -> 不切换 -> 修复后重试；
- 根思维图记录选择/视口 -> 进入已有 Map Space -> 在下层编辑、平移和缩放 ->
  `Esc`/返回：下层内容和视口保持，父层内容、选择与视口恢复；
- 普通单选 -> 画布保持安静且不出现上下文工具条；节点右键 -> 对象菜单 -> “下钻为…”
  -> 中央选择层 -> 选择“思维图”但尚未创建 -> 确认后创建永久 Map Space 并进入；
  返回后父节点不带角标、关系线末端出现 Map 概要子节点 -> 概要只显示前三个直接下级和
  必要的 `...`，不泄露第四项或更深后代；首次返回适应新的父层全图，主主题、锚点与概要
  都在视口内，后续往返恢复原视口和概要/普通节点交互目标 -> 点击只选择、双击或悬停后点击角标进入同一 Map；
- 再次对普通节点调用下钻 -> 选择“流程” -> 父层概要子节点排除起止节点，并按
  `步骤1→步骤2→步骤3...→最后一步` 有界显示 -> 点击只选择、双击或角标进入 ->
  新 Flow 只生成一个普通步骤 -> 从左侧图形栏点击添加
  “起止”并删除，再把“判断”拖到画布且按中心线吸附 -> 悬停节点后依次从右、下
  方向点进入宽松命中区：外围淡点变为箭头并显示半透明步骤与连线，点击后真实对象与预览
  位置一致；同一方向连续创建时保留旧分支并落到最近空闲侧向轨道 -> 选中节点后一键创建
  “判断”并立即编辑 -> 拖动节点后
  刷新仍保留本地位置，但 Markdown 区块不出现坐标 -> 从两个不同来源的连线点依次拖到
  同一已有目标 -> 两条转移都存在、
  目标只出现一次且自动布局稳定 -> 连线默认保持圆角正交、绕过节点且交叉处出现横跨桥 ->
  点击一条线后分别修改线型、虚实、线宽、颜色和两个端点样式 -> 拖动中央理线柄避开一条
  重叠线路，取消拖动不提交，刷新保留本地走廊，恢复自动理线后走廊消失且 Markdown 始终
  不含走廊坐标 -> 把原起点从节点右侧重接到左侧并确认旧走廊被清除，刷新后端点与外观
  保持，并确认视觉端点样式不改变关系方向 -> 编辑透明无边框的分支名称 -> 对直线/曲线
  只验收 renderer 外观，不能误报为已获得正交避障或跨线桥保证 ->
  `Esc` 取消一次进行中的
  连线且不返回上层 -> 用方向键返回旧节点 -> 右键菜单继续可改类型/编辑/删除，并可通过
  搜索选择层汇合到已有步骤/撤销 -> 返回：概要子节点可见、父层状态恢复；重新进入
  Flow 时内容与独立视口保持，不能重新创建或跳回根思维图；选中概要后复制得到概要文字，
  拖到无子 Space 的节点则整张 Space 改挂且可一次撤销，拖到无效目标或指针取消不改变内容；
- 选中概要 -> 删除 -> 必须先出现明确说明“原节点保留”的二次确认；取消后概要、Space 和
  选择仍在，确认后只移除 Space、父节点保留，并可一次撤销；
- 选中概要 -> 命令面板：只出现概要能力与共享的文档/视口操作，不出现创建子节点、
  创建父节点、同级创建、提升或节点粘贴；`Tab` 与 `Command+Enter` 不改结构，`Enter`
  进入下层图而不是下发普通节点的“创建同级”命令，`←` 选回锚点；在复制后删除或确认
  弹窗存在期间替换/移动原 Space，旧请求必须失效，不能删除新 Space 或锚点节点；
- Map/Flow 内容保存 -> Markdown 中普通大纲与版本化 `laniakea` 区块共同读回；只改
  Space 视口 -> Markdown 正文和备份数量不变；外部移动锚点后 ref 重算仍绑定同一当前节点，
  无效/重复/悬空锚点、坏树或坏边则触发 rich-source 保护而不是丢弃 Space 后覆盖；
- 删除带下层图的节点/祖先 -> 子 Space 同次删除并可一次撤销；复制普通子树不得留下
  指向原 Space 的重复概要；从 Map Space 继续创建嵌套 Map/Flow -> 返回路径逐层恢复；
  搜索子 Space 节点 -> 进入正确 Space 与节点；
- 新建/打开 A 未完成 -> 用户发起 B -> A 后完成；导入 rich source -> 另存 -> 自动保存；
- 分别从两个目录打开同名 Markdown -> 另存其中一份到第三个目录 -> 继续编辑并等待
  自动保存：标题旁短标签、切换器“正在编辑”、活动文档索引、正文摘要和磁盘最终字节
  必须一致指向真实写入目标；其他目录的同名旧稿只能出现在“其他最近文档”。rich
  Markdown 未绑定副本必须显示“待另存 · 来源”，不能把来源路径描述为保存位置；
- 多选 -> 删除/剪切/粘贴 -> 一次撤销/重做；折叠后全选；浮动分支移动、复制、搜索；
- 选中目标节点 -> 系统剪贴板分别放入普通单行、复制出的单节点 Markdown 与多节点
  大纲 -> `Command+V`：原生 paste 事件直接创建子节点，不调用二次剪贴板读取、不出现
  Paste 授权浮窗；单节点不得保留列表标记，多节点层级不丢失，整次操作一次撤销；
- 多选同级/跨级/祖先与后代 -> 拖到空白或有效父节点 -> 整组预览、相对位置、归一化
  根集合与连续插入顺序一致 -> 一次撤销/重做；选择含主原点时主原点必须在拖动开始前
  从操作集合和可见选择中排除，不能出现“仍选中但未移动”的假象；
- 拖动分支到已有子节点的上方/中间/下方 -> 关系预览位置 -> 松手 -> 父节点与
  `children` 顺序一致；再用 `Command+↑/↓` 调整，拖拽与键盘不得形成两套排序语义；
- 高密度分支中原父级与邻近父级磁性范围重叠 -> 将当前节点拖到原父级第一个子节点位置
  -> 预览和松手都保留原父级且 `children` 顺序变为第一位；拖出原父级范围再进入邻近父级
  才能改挂载，不能以“请使用快捷键”代替直接拖拽；
- 拖动已出现关系预览 -> `Esc`/失焦/页面隐藏/指针捕获丢失/文档切换 -> 松手：所有
  路径都保留原结构、清除预览与捕获，并且下一次普通拖动不继承旧目标；
- 分别从普通节点和概要代理启动拖动 -> 越过各自阈值 -> 有效/无效目标 ->
  `Esc`/失焦/页面隐藏/指针取消/捕获丢失：共享生命周期都释放捕获且不遗留目标；
  随后普通拖动仍按分支重排/改父级提交，概要拖动只按 Space 改挂提交，不能互换 mutation；
- 分别在 Map 与 Flow 中开始画布平移或框选，并在 Flow 中开始图形栏拖动、节点拖动、
  连线、重连或手动理线后触发 `Esc`/失焦/页面隐藏：当前操作和边缘自动平移同时停止、视口不再
  漂移且仍留在当前 Space；再次按 `Esc` 才返回上层。任一直接操作期间滚轮不得改变
  起始视口或造成图形落点偏移；
- 分别编辑一个思维节点和流程节点，连续输入两版文字 -> 在编辑框内撤销/重做只改变当前
  草稿且不调用画布历史 -> 提交后画布撤销恢复正常 -> 再次进入同一节点时不能撤销到上一
  次编辑会话；输入法组合期间不得记录或恢复半成品预编辑文字；编辑中切到其他应用、窗口
  失焦或页面暂时隐藏时草稿和编辑态都保留，真正关闭应用时才走退出前提交与保存；
- 展开多后代分支 -> 记录全部一级分支画布位置 -> 折叠一个深层分支 -> 一级分支
  与主原点锚点不变且后代隐藏；再次展开时被操作分支保持锚点、相邻分支无重叠；
- 从空白文档打开/粘贴大图 -> 自动适应当前新布局；高度超过日常缩放范围时进入全图
  概览且完整内容位于视口内，继续放大不跳变；
- 文本框/标题/搜索内的原生快捷键与画布快捷键；编辑态 Space、框选、平移和 Esc；
- 选中或编辑节点 -> 手动平移到该节点完全离开视口 -> 等待超过视口保存防抖并触发一次
  文本/布局重排：视口仍停在用户位置；只有真正切换选择、搜索跳转或显式聚焦命令才揭示
  节点。编辑时点击空白则只提交一次并清空选择，不再把刚编辑节点留为选中；
- 聚焦搜索输入 -> 光标与局部载体清楚可见但没有画布节点式紫色选中环；打开最近文档后
  悬停“更多” -> 子菜单不属于滚动列表的裁切树、可跨边界完整显示并允许指针移入，滚动
  列表关闭旧菜单，Esc 关闭并把焦点返回触发项；
- 单选普通节点按 `Command+Enter` -> 新空父节点立即进入编辑并精确替换原节点的位置，
  原节点及整棵后代完整留在新父节点之下；对主原点和浮动根执行时原位包裹，撤销一次恢复；
- 已有节点文字 -> 中文拼音预编辑 -> 候选上屏：已有文字、拼音与光标在组词期间可见，
  节点外框不漂移，提交后只按最终文字重排；空文本组合输入不能代替这个序列；
- 混合中英文、数字、标点连续输入 -> 节点按当前运行字体逐字扩宽 -> 达到各角色上限后
  才换行并按实际行数增高；显示态与编辑态的内容宽度、换行点和后代横移保持一致；
- 中心节点与普通节点分别输入显式换行和足以自动折行的文字 -> 中心节点显示/编辑保持
  居中，其他节点显示/编辑/拖拽预览都从同一左边缘排版，切换状态时文字不横跳；对
  单行普通节点测量外框、文字和边框，左右留白相等，布局不得另加只暴露在右侧的余量；
- `# 未命名思维` + 有意义文件名/主原点 -> 打开 -> 恢复画布缓存 -> 最近文档切换；
  标题必须离开占位值，显式非占位一级标题仍保持权威；
- 父节点因长文本变宽 -> 后代重排 -> 连线/视口裁剪/命中区域；10,000 节点下搜索、
  布局、选择、缩放、拖动、保存和切换。
- 同一短文本分别位于二级与三级 -> 三级节点的字号、高度和留白形成肉眼可辨的紧凑层级，
  不能只用一个勉强不相等的数值通过测试；同时选中、编辑、
  中文输入与多行增长仍保持文字位置一致；触控板连续缩放在细小反向增量下可逆，返回
  上层使用共享 Armorial 图标组件而不是字体字符。

前台 UI 保持单一编辑器和按需覆盖层。不要为诊断、Agent、存储或 protocol 增加侧栏、
仪表盘和常驻解释。保存/打开超过一秒才展开状态，失败保持并给恢复动作；普通成功不
长期占据画布。视觉与顺手程度仍由 owner 体验验收，自动截图不是通过证明。

## 高频与大图证据

任何声称“流畅”“适合大图”或 Agent 高频可用的改动，都用同一机器、同一 fixture、
同一 warm/cold 状态做 before/after。至少记录：1k/10k 节点解析与布局，首屏和交互帧
p50/p95/p99，搜索全扫描，500/5,000 节点响应字节，100-operation update，8 路读、
2 路同 revision 写冲突，RSS/heap、文件描述符、锁/临时文件残留和失败率。不得用平均
函数耗时替代真实浏览器帧、MCP transport 或磁盘提交尾延迟。

概览态拖动的候选命中使用从当前布局生成的纵向空间索引；`nodeDrag.test.ts` 的
10,000 节点用例机械限制单次探针只进入附近候选，并与全量命中结果做等价比较。
这个用例只防止重新退化成逐节点扫描，不替代真实浏览器的 input-to-visible 帧测量。
在本机安装 Chrome，或通过 `CHROME_PATH` 指定兼容浏览器后，运行
`npm run measure:overview-drag` 可从真实文件导入入口建立 10,000 节点临时文档，
在 1600×1000 概览态执行真实 pointer 序列，要求放大后挂载窗口确实收缩，并输出
pointer handler、首次反馈 mutation、持续帧、布局释放、heap 和残留状态。输出
`measured` 只表示这些观测实际发生；它没有内置“流畅”阈值，也不替代同环境 before/after
或 owner 体验判断。`releaseToSixStableFrames` 包含测量器主动等待的六帧下限，不得写成
纯粹的产品响应耗时。

运行 `npm run measure:bundle` 获取每个构建 chunk 的原始/gzip 字节及模块归因。入口拆包
只能声明缓存、解析或按需加载边界发生变化；总 JavaScript 字节没有下降时，不得把构建
警告消失写成总下载性能改善。

当前没有批量文件 API；不要为跑分虚构。未来若增加批量，必须先定义批内局部失败、
单文件 revision、总文件/节点/字节/时间预算、取消与原子性范围，不能把单文件 8 MiB
或 100 operations 简单乘以批大小。

## 可重跑证据与分 lane 结论

开发回归：

```sh
npm run check:regression
```

它覆盖 Web/core 单元与 DOM 测试、Web 构建、MCP 类型/构建与真实 stdio 流、40 轮
跨进程并发写、Rust 存储测试。它不是安装态、桌面交互或 owner 体验验收。

桌面真实启动基线：

```sh
npm run check:desktop-runtime
```

该命令用独立产品名、bundle ID 和应用数据目录重建 `Laniakea Verify.app`，并以隐藏、后台
方式启动；不得终止、复用、覆盖 owner 正在使用的 `Laniakea.app`，也不得抢走其前台焦点而
意外结束正在进行的节点编辑。它只证明隔离构建与启动基线。文件切换、外部冲突、另存、
全局快捷键、关闭/退出握手和视觉操作仍需在这份新构建上执行完整序列。

最终分别报告：

- **开发回归**：当前 `check:regression` 与改动接缝的最小负向回归；
- **Agent runtime**：当前 bundled/installed plugin、四工具发现、真实文件写读回、
  revision 冲突、rich 保护、错误载体与输出成本；
- **Web runtime**：真实浏览器 IndexedDB、多标签页、备份/恢复、离线和刷新；
- **Desktop runtime**：新 `.app` 的文件、快捷键、窗口、退出与磁盘读回；
- **Capability/Procedure**：当前 `NOT PRESENT`；
- **业务/体验**：owner 给 `OK / 不OK / 待验收`，不得由上面任一绿灯代替。

每个技术 lane 使用 `PASS / FAIL / BLOCKED`。写入缺陷的 reproducer 必须包含初始文件
字节、路径/别名、revision、操作顺序、并发者、预期最终文件、实际最终文件，以及锁、
临时文件、备份和活动文档等残留状态。
