## 结果与补修

保留单一画布与按需操作。去掉连线文字、方向创建点和图形栏重复讲解点击/拖动的
悬停提示；浏览器文档库保留真实保存边界，移除定期备份劝告。无障碍名称和必要的
失败恢复入口继续保留，没有新增常驻控件。

用户随后用截图明确指出，操作提示之外，顶部“本地草稿 / 流程”和图形下的
“步骤 / 判断 / 起止”也是多余的常驻解释。本轮据此进一步删除这些可见标签，
保存位置仅在文档切换器内出现，图形栏只留三种图形与原有点击/拖放能力；按钮仍有
无障碍名称。文档切换触发器不再通过悬停重复报告保存位置，草稿条目也去掉操作劝告。
相应产品文档和既有文案断言按此次明确的用户决定更新。

复核发现并修正以下未闭合问题：

- Flow 的 Esc 新判断之前仍有画布焦点拦截，焦点停在顶栏时不能返回。现在只把
  结构编辑限制在画布，保留菜单、编辑器和拖动对 Esc 的优先处理。桌面实际点击又
  复现了菜单打开后焦点仍在画布、Esc 越过菜单返回上层的问题；文档和更多菜单
  现在点击时明确聚焦触发器，Flow 对展开触发器让出按键处理。
- 状态外壳有展开后备，内部文字却仍完全依赖动画帧。暂停动画帧时可能透明；原暂存
  CSS 又使透明按钮可点击。补齐文字显示后备，并恢复不可见提示的指针屏蔽。
- Flow 启用全局快捷键后，视图命令仍发往已卸载的思维图；命令面板还显示上层节点
  操作。现在视图命令连接当前流程视口，Flow 面板只暴露可用的全局命令，执行入口
  同样检查目标，复制 Markdown 使用整份文档。
- 旧标签页携带已删除对象的布局引用时，视图保存触发结构校验错误。现在按当前
  正文中的节点/连线过滤布局引用，保留较新正文及版本；没有放宽文档校验。
- 改节点类型时仅使用估算文字尺寸，且未覆盖自动布局节点。现在用当前渲染的坐标
  和测量方式保持中心位置，并冻结当时的可见布局。
